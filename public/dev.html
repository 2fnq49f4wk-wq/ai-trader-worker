AI로 사이트 만드는 실제 설정

LUX-INV(AI 모의주식 사이트)를 만들면서 실제로 쓰는 구조와 규칙을 그대로 공개함. 따라 하면 됨.

1. 전체 구조

폰으로 AI한테 말함→AI가 코드 고치고 깃허브에 올림→깃허브 액션 검사 226개→통과하면 클라우드플레어 자동 배포
  • 서버: 클라우드플레어 워커 하나. 데이터는 D1(데이터베이스), 파일은 R2
  • 코드: 깃허브 저장소 하나. main 에 올라가는 순간 배포됨
  • 연결: 클라우드플레어에서 API 토큰 하나 만들어서 깃허브 시크릿(CLOUDFLARE_API_TOKEN)에 넣으면 끝
# .github/workflows/deploy.yml 핵심만
on: push (main)
steps:
  - 검사 돌리기 (하나라도 실패하면 여기서 멈춤)
  - wrangler deploy

2. CLAUDE.md — AI한테 주는 규칙 파일

저장소 맨 위에 두면 클로드 코드가 매번 읽음. 우리가 실제로 넣어둔 규칙 중 효과 컸던 것:

  1. 배포 순서 고정 — 검사 → 커밋 → 푸시. 검사 통과 못 하면 배포 안 함
  2. 내 말도 그대로 믿지 말 것 — "장 닫혔어" 해도 실제 데이터로 확인하고 움직이게 함
  3. 최신 코드 위에서만 작업 — 옛날 버전 위에서 작업하다 기능 날아간 사고 이후 생김
  4. 비용 한도 안에서 설계 — 사람 수가 늘어도 서버 일이 안 늘게(캐시)
  5. AI 바꾸면 화면도 같이 — 기능만 바꾸고 화면은 옛날 그대로인 실수 방지
  6. 인수인계 파일 — AI 여러 개를 쓰니까 끝날 때마다 AI_HANDOFF.md 에 뭘 했는지 적게 함

3. 자주 쓰는 클로드 코드 명령어

  • /init 처음 한 번. CLAUDE.md 를 만들어 줌
  • /compact 대화가 길어지면 요약해서 이어감
  • /resume 어제 하던 대화 다시 불러오기
  • /code-review 올리기 전에 버그 찾기
  • /loop 정해진 간격으로 반복 확인

스킬: .claude/skills/이름/SKILL.md 에 순서를 적어두면 /이름 으로 불러 쓰는 나만의 명령어가 됨.

4. 돈 안 나가게 하는 규칙

  • 한 번 읽은 데이터는 캐시해서 모두가 같이 봄. 화면 열 때마다 DB 읽으면 청구서 나옴(실제로 나옴)
  • 개인 데이터는 화면이 계산하고 저장은 모아서 한 번에
  • 사용량은 매일 자동으로 재서 한도 넘으면 검사가 빨간불 켬
